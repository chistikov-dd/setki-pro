## Введение

SETKI Desktop — это система управления турнирами для единоборств. Как администратор, вы отвечаете за:

- ✅ Подготовку турнира и скачивание данных
- ✅ Выдачу PIN-кодов судьям
- ✅ Мониторинг активных поединков
- ✅ Управление режимами работы (online/offline)
- ✅ Синхронизацию результатов с сервером

## Установка и настройка

### Системные требования

**Минимальные:**
- OS: Windows 10/11, macOS 12+, Linux (Ubuntu 20.04+)
- RAM: 4 GB
- Диск: 500 MB свободного места
- Разрешение экрана: 1280x720

**Рекомендуемые:**
- OS: Windows 11, macOS 14+, Ubuntu 22.04+
- RAM: 8 GB
- Диск: 1 GB
- Разрешение экрана: 1920x1080 или выше

### Установка

#### Windows
1. Скачайте `SETKI-Desktop-Setup.exe` из релизов
2. Запустите установщик
3. Следуйте инструкциям мастера установки
4. Приложение будет доступно в меню Пуск

#### macOS
1. Скачайте `SETKI-Desktop.dmg`
2. Откройте DMG файл
3. Перетащите SETKI Desktop в папку Applications
4. При первом запуске: Системные настройки → Конфиденциальность → Разрешить

#### Linux (AppImage)
1. Скачайте `SETKI-Desktop.AppImage`
2. Сделайте файл исполняемым:
   ```bash
   chmod +x SETKI-Desktop.AppImage
   ```
3. Запустите:
   ```bash
   ./SETKI-Desktop.AppImage
   ```

### Первый запуск

1. Откройте приложение
2. Выберите **"Вход как администратор"**
3. Введите логин и пароль от аккаунта setki.pro
4. Вы попадете в панель администратора

## Подготовка к турниру

### Workflow: Турнир с интернетом

```
1. Вход → 2. Выбор турнира → 3. Скачивание данных →
4. Выдача PIN → 5. Мониторинг → 6. Автосинхронизация
```

### Workflow: Турнир без интернета (LAN)

```
1. [С интернетом] Скачать турнир
2. [На турнире] Запустить локальный сервер
3. Показать IP адрес судьям
4. Судьи подключаются по IP
5. [После турнира] Выгрузить результаты
```

### Шаг 1: Создание турнира на setki.pro

**Важно!** Турнир должен быть создан на https://setki.pro перед использованием Desktop приложения.

1. Зайдите на setki.pro
2. Создайте турнир
3. Добавьте сетки и участников
4. Сгенерируйте сетки
5. Запомните ID турнира или название

### Шаг 2: Скачивание турнира в приложение

1. В панели администратора нажмите **"Выбрать турнир"**
2. Выберите турнир из списка
3. Нажмите **"Скачать турнир"**
4. Дождитесь завершения (индикатор прогресса)

**Что скачивается:**
- Все сетки турнира
- Список участников
- Расписание поединков
- PIN-коды для судей

**Размер:** ~100-500 KB на турнир

### Шаг 3: Проверка PIN-кода

1. На главном экране вы увидите:
   ```
   Текущий турнир: Чемпионат России 2025
   PIN-код: 123456
   ```
2. **Запишите PIN-код** — он нужен судьям для входа
3. PIN генерируется автоматически при скачивании турнира

## Режимы работы

SETKI Desktop поддерживает 3 режима работы:

### 1. Работа через интернет (Online Mode)

**Когда использовать:** Турнир проходит в месте с стабильным интернетом.

**Преимущества:**
- Автоматическая синхронизация с setki.pro
- Мгновенное обновление результатов в облаке
- Доступ к результатам из любой точки

**Настройка:**
1. Режим работы → **"Работа через интернет"**
2. Все готово! Судьи тоже должны выбрать этот режим

### 2. Локальный сервер (Local Server Mode)

**Когда использовать:** Турнир без интернета, 10+ судейских столов.

**Архитектура:** Мастер-Сервер
- Ваш компьютер = сервер
- Судейские компьютеры = клиенты
- Все подключены в одну локальную сеть (LAN/Wi-Fi)

**Настройка:**

1. **На компьютере администратора:**
   - Режим работы → **"Запустить локальный сервер"**
   - Вы увидите:
     ```
     🟢 Локальный сервер запущен
     IP: 192.168.1.100:8081
     Подключено судей: 0
     ```
   - **Запишите IP адрес** (например, `192.168.1.100:8081`)

2. **На компьютерах судей:**
   - Режим работы → **"Подключение к локальному серверу"**
   - Введите IP: `192.168.1.100:8081`
   - Нажмите "Подключиться"
   - Вернитесь назад (кнопка "Назад")
   - Войдите как судья (PIN + имя + номер стола)

**Важно!**
- Администратор НЕ выключает компьютер до конца турнира
- Все судьи должны быть в одной сети с администратором
- Порты: 8081-8091 (автоматический выбор свободного)

**Технология:**
- Protocol: HTTP/WebSocket
- Discovery: mDNS (`_setki._tcp.local`)
- Sync: Real-time через WebSocket

### 3. Локальный клиент (Local Client Mode)

**Когда использовать:** Вы судья, подключаетесь к локальному серверу администратора.

**Настройка:** См. раздел выше "На компьютерах судей"

## Управление судьями

### Панель мониторинга судей

После запуска локального сервера или в online режиме вы видите панель:

```
┌─────────────────────────────────────────────────┐
│  Подключенные судьи (5)                          │
├─────────────────────────────────────────────────┤
│  Стол 1  │  Иванов Иван      │  🟢 Активен       │
│  Стол 2  │  Петров Петр      │  🟢 Активен       │
│  Стол 3  │  Сидорова Анна    │  🔴 Офлайн        │
│  Стол 4  │  Кузнецов Олег    │  🟢 Активен       │
│  Стол 5  │  Новикова Мария   │  🟢 Активен       │
└─────────────────────────────────────────────────┘
```

**Статусы:**
- 🟢 **Активен** — судья онлайн, может судить
- 🔴 **Офлайн** — судья отключился или потерял связь
- 🟡 **В поединке** — судья судит поединок

### Уникальность номеров столов

**Важно!** Каждый номер стола уникален:
- Два судьи **не могут** войти с одинаковым номером стола
- При попытке второго входа — ошибка "Номер стола N уже занят"
- При выходе судьи — номер освобождается автоматически

### Уведомления о судьях (только в Local Server Mode)

При подключении/отключении судей вы получаете toast-уведомления:

```
🟢 Судья Иванов Иван подключился к столу №3
🔴 Судья Петров Петр отключился от стола №5
```

### Панель активных поединков

```
┌─────────────────────────────────────────────────┐
│  Активные поединки (3)                           │
├─────────────────────────────────────────────────┤
│  Мужчины -70кг  │  Иванов vs Петров             │
│  Стол: 1        │  12:8  ⚠️2:⚠️1  ⏱️ 02:45      │
├─────────────────────────────────────────────────┤
│  Женщины -60кг  │  Сидорова vs Новикова         │
│  Стол: 3        │  5:7   ⚠️0:⚠️3  ⏱️ 01:20      │
├─────────────────────────────────────────────────┤
│  Мужчины -80кг  │  Кузнецов vs Морозов          │
│  Стол: 4        │  0:0   ⚠️0:⚠️0  ⏱️ 05:00      │
└─────────────────────────────────────────────────┘
```

**Информация:**
- Сетка и поединок
- Текущий счет (красный:синий)
- Предупреждения (⚠️)
- Таймер
- Номер стола

**Обновление:** Каждые 5 секунд (автоматически)

### Критические ситуации

**⚠️ Предупреждение о дисквалификации:**
Если у спортсмена 3 предупреждения — панель подсвечивает поединок желтым.

**🔴 Критическая ситуация:**
- Таймер истек, но поединок не завершен
- Подсветка красным цветом

## Синхронизация данных

### Автоматическая синхронизация (Online Mode)

В online режиме синхронизация происходит автоматически:
- **Каждое действие** судьи → сразу отправляется на сервер
- **Конфликты** разрешаются по timestamp (последнее изменение побеждает)
- **Offline режим** — данные сохраняются локально, синхронизируются при восстановлении связи

### Ручная синхронизация (Local Server Mode)

После турнира в локальном режиме:

1. Переключитесь обратно в **"Работа через интернет"**
2. Нажмите кнопку **"Выгрузить результаты"**
3. Дождитесь завершения (индикатор прогресса)
4. Проверьте результаты на setki.pro

**Важно!**
- Синхронизируются только **завершенные** поединки
- Незавершенные поединки остаются локально
- При конфликтах — последнее изменение побеждает

### Индикатор синхронизации

В правом верхнем углу:
- 🟢 **Синхронизировано** — все данные в облаке
- 🟡 **Синхронизация...** — идет отправка данных
- 🔴 **Офлайн** — нет связи с сервером
- 📊 **5 изменений** — количество несинхронизированных изменений

## Troubleshooting

### Проблема: Судья не может подключиться к локальному серверу

**Решения:**
1. Проверьте, что администратор запустил сервер (должен быть IP адрес)
2. Проверьте, что судья и администратор в одной сети
3. Проверьте правильность IP адреса (скопируйте-вставьте)
4. Проверьте firewall (Windows Defender может блокировать порты 8081-8091)
5. Попробуйте ping администратора:
   ```bash
   ping 192.168.1.100
   ```

### Проблема: "Номер стола уже занят"

**Причины:**
- Другой судья уже вошел с этим номером
- Предыдущая сессия судьи не закрылась корректно

**Решения:**
1. Проверьте панель подключенных судей
2. Если судьи с этим номером нет — перезапустите локальный сервер
3. Используйте другой номер стола

### Проблема: Результаты не синхронизируются

**Решения:**
1. Проверьте индикатор синхронизации (🟢/🟡/🔴)
2. Проверьте интернет-соединение
3. Нажмите "Выгрузить результаты" вручную
4. Проверьте логи (Меню → Настройки → Экспорт логов)

### Проблема: Локальный сервер не запускается

**Ошибка:** "Все порты 8081-8091 заняты"

**Решения:**
1. Закройте другие приложения, использующие эти порты
2. Перезагрузите компьютер
3. Проверьте firewall

### Проблема: Поединок "завис" в статусе in_progress

**Решения:**
1. Найдите поединок в панели активных поединков
2. Свяжитесь с судьей — он должен завершить поединок
3. Если судья недоступен — завершите поединок вручную через админ-панель на setki.pro

### Проблема: Низкая производительность при 15+ судьях

**Оптимизация:**
1. Увеличьте polling interval (Настройки → Продвинутые → Polling: 10 сек)
2. Отключите debug логи (Настройки → Логирование → Уровень: ERROR)
3. Закройте ненужные приложения на компьютере-сервере
4. Используйте проводное Ethernet вместо Wi-Fi

**Текущие лимиты:**
- Рекомендуемое количество столов: **15-20**
- Максимальное (протестировано): **20**
- CPU: 15-25% peak
- Latency: 100-200ms

### Проблема: База данных повреждена

**Ошибка:** "SQLite error: database disk image is malformed"

**Решения:**
1. **НЕ ПАНИКУЙТЕ** — данные в облаке (если был online mode)
2. Закройте приложение
3. Найдите файл базы данных:
   - Linux: `~/.local/share/com.chistikov.tauri-app/setki.db`
   - Windows: `%APPDATA%\com.chistikov.tauri-app\setki.db`
   - macOS: `~/Library/Application Support/com.chistikov.tauri-app/setki.db`
4. Сделайте backup:
   ```bash
   cp setki.db setki.db.backup
   ```
5. Удалите файл и перезапустите приложение
6. Скачайте турнир заново

## Производительность и масштабирование

### Текущие метрики (протестировано)

**Конфигурация:**
- Столов: 15-20
- Режим: Local Server
- OS: Linux/Windows

**Результаты:**
- CPU: 15-25% peak (было 25-42% до оптимизаций)
- RAM: ~200MB
- Latency: 100-200ms (было 300-500ms)
- SQLite connections: 20 (pool)
- WebSocket rate limit: 10 msg/sec

**Оптимизации (декабрь 2025):**
- ✅ SQLite Connection Pool 5→20
- ✅ SQLite WAL mode
- ✅ WebSocket Rate Limiting
- ✅ Admin Polling Debounce (300ms)
- ✅ Request Stacking Prevention

### Рекомендации по масштабированию

**10-15 столов:** Стандартная конфигурация, работает отлично

**15-20 столов:** Рекомендуемый максимум
- Используйте проводной Ethernet
- Выделенный компьютер для сервера (не судейство + сервер)
- RAM: 8GB+

**20+ столов:** Не рекомендуется
- Возможны задержки синхронизации
- Рассмотрите разделение на несколько зон с отдельными серверами

## Резервное копирование

### Автоматическое

В online режиме все данные автоматически в облаке (setki.pro).

### Ручное (Local Server Mode)

1. Найдите файл базы данных (см. раздел Troubleshooting)
2. Скопируйте `setki.db` на USB/облако после каждой сессии:
   ```bash
   cp setki.db ~/Backup/setki-$(date +%Y%m%d-%H%M%S).db
   ```

### Восстановление

1. Закройте приложение
2. Замените `setki.db` на backup-версию
3. Запустите приложение

## Лучшие практики

### Перед турниром (за 1 день)

- [ ] Скачайте турнир с setki.pro
- [ ] Проверьте PIN-код
- [ ] Протестируйте вход как судья на тестовом компьютере
- [ ] Проверьте синхронизацию
- [ ] Сделайте backup базы данных

### В день турнира (за 1 час)

- [ ] Подключите компьютер к сети (проводной предпочтительно)
- [ ] Запустите локальный сервер (если без интернета)

- [ ] Проверьте подключение тестового судейского компьютера

### Во время турнира

- [ ] Мониторьте панель активных поединков
- [ ] Следите за подключенными судьями
- [ ] НЕ выключайте компьютер-сервер
- [ ] Делайте backup каждые 2 часа (если Local Server)

### После турнира

- [ ] Дождитесь завершения всех поединков
- [ ] Выгрузите результаты на setki.pro
- [ ] Проверьте результаты на сайте
- [ ] Сделайте финальный backup базы данных
- [ ] Экспортируйте логи (на случай споров)
