# Профили для Тестирования Оффлайн Режима

Эта документация объясняет как тестировать оффлайн режим (локальный сервер) на одном компьютере.

## 🎯 Зачем нужны профили?

При разработке нужно тестировать взаимодействие между админом и судьями через локальный сервер.
Профили позволяют запустить **несколько независимых экземпляров** приложения на одном компьютере,
каждый с собственной базой данных SQLite.

## 📁 Структура данных

Каждый профиль использует свою директорию и порт:

```
~/.setki-keeper-admin/       # Профиль админа
  └── data/
      ├── setki.db           # База данных админа
      └── setki.log          # Логи админа
  Порт Vite: 1420 (HMR: 1421)

~/.setki-keeper-judge1/      # Профиль судьи 1
  └── data/
      ├── setki.db           # База данных судьи 1
      └── setki.log          # Логи судьи 1
  Порт Vite: 1430 (HMR: 1431)
```

По умолчанию (без профилей): `~/.setki-keeper/data/` (порт 1420)

## 🚀 Как использовать

### Вариант 1: Shell скрипты (Linux/macOS)

#### Запуск админа:
```bash
./dev-admin.sh
```

#### Запуск судьи в другом терминале:
```bash
./dev-judge1.sh
```

### Вариант 2: Напрямую через npm (любая ОС)

#### Терминал 1 - Админ:
```bash
export SETKI_DATA_DIR="$HOME/.setki-keeper-admin"
export VITE_PORT=1420
export VITE_HMR_PORT=1421
npm run tauri dev
```

#### Терминал 2 - Судья 1:
```bash
export SETKI_DATA_DIR="$HOME/.setki-keeper-judge1"
export VITE_PORT=1430
export VITE_HMR_PORT=1431
npm run tauri dev
```

**Windows (PowerShell):**
```powershell
# Терминал 1 - Админ
$env:SETKI_DATA_DIR="$env:USERPROFILE\.setki-keeper-admin"
$env:VITE_PORT=1420
$env:VITE_HMR_PORT=1421
npm run tauri dev

# Терминал 2 - Судья 1
$env:SETKI_DATA_DIR="$env:USERPROFILE\.setki-keeper-judge1"
$env:VITE_PORT=1430
$env:VITE_HMR_PORT=1431
npm run tauri dev
```

## 🧪 Workflow тестирования оффлайн режима

### 1. Подготовка (с интернетом)

**Терминал 1 - Админ:**
```bash
./dev-admin.sh
```

В приложении:
1. Выбрать "Вход как администратор"
2. Войти с учетными данными
3. Выбрать турнир
4. **"Скачать турнир"** → данные сохранятся в `~/.setki-keeper-admin/data/setki.db`

### 2. Запуск локального сервера (без интернета)

**В окне админа:**
1. "Режим работы" → "Запустить локальный сервер"
2. Записать IP адрес (например, `192.168.1.100:8081`)
3. Должно появиться уведомление: "Локальный сервер запущен на ..."

### 3. Подключение судьи

**Терминал 2 - Судья:**
```bash
./dev-judge1.sh
```

В приложении:
1. "Режим работы" → "Подключение к локальному серверу"
2. Ввести IP: `192.168.1.100:8081`
3. "Вход как судья"
4. Ввести:
   - PIN-код турнира
   - Имя: "Тестовый судья"
   - Номер стола: **1**

### 4. Проверка

**В окне админа:**
- Должно появиться уведомление: "Судья Тестовый судья подключился к столу №1"
- В панели "Активные столы" должен отобразиться судья

**В окне судьи:**
- Должны загрузиться сетки турнира
- Можно выбрать сетку и судить матчи

### 5. Тестирование синхронизации

1. Судья добавляет баллы/предупреждения
2. Данные сохраняются в БД судьи (`~/.setki-keeper-judge1/data/setki.db`)
3. **HTTP POST** отправляется на сервер админа
4. Данные сохраняются в БД админа (`~/.setki-keeper-admin/data/setki.db`)
5. Админ видит обновления через WebSocket

## 🔍 Отладка

### Проверка логов:

```bash
# Логи админа
tail -f ~/.setki-keeper-admin/data/setki.log

# Логи судьи
tail -f ~/.setki-keeper-judge1/data/setki.log
```

### Проверка БД:

```bash
# База админа
sqlite3 ~/.setki-keeper-admin/data/setki.db "SELECT * FROM judge_sessions;"

# База судьи
sqlite3 ~/.setki-keeper-judge1/data/setki.db "SELECT * FROM sync_queue;"
```

### Очистка данных:

```bash
# Удалить все профили
rm -rf ~/.setki-keeper-admin ~/.setki-keeper-judge1

# Удалить только базы (сохранить логи)
rm ~/.setki-keeper-admin/data/setki.db
rm ~/.setki-keeper-judge1/data/setki.db
```

## ⚠️ Важные моменты

1. **Один судья = один стол**: Нельзя подключиться к столу который уже занят
2. **WebSocket только для админа**: Уведомления о подключении судей приходят через WebSocket
3. **HTTP для синхронизации матчей**: Судьи отправляют данные через POST запросы
4. **Offline-first**: Данные сначала сохраняются локально, затем отправляются на сервер

## 🎓 Расширение для большего количества судей

Если нужно протестировать больше судей, создайте дополнительные профили:

```bash
# dev-judge2.sh
export SETKI_DATA_DIR="$HOME/.setki-keeper-judge2"
npm run tauri dev

# dev-judge3.sh
export SETKI_DATA_DIR="$HOME/.setki-keeper-judge3"
npm run tauri dev
```

Каждый судья должен использовать **уникальный номер стола**!

## 📊 Мониторинг

В админской панели доступна информация о:
- Активных судьях (имя + номер стола)
- Времени подключения
- Занятых сетках

Все это обновляется в реальном времени через WebSocket.
