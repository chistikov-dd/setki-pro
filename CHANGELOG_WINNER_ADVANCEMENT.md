5. **Обновление следующего матча** (строки 1310-1341)
   - UPDATE с json_set() для вставки полных данных победителя
   - INSERT в sync_queue для синхронизации с сервером

6. **Логирование** (строки 1224, 1240, 1288, 1311, 1343-1348)
   - Отладочные println!() для трассировки выполнения

## 🚀 Использование

### Для пользователя

Никаких изменений в UI! Функциональность работает автоматически:

1. Судья завершает матч (кнопка "Завершить" или Enter)
2. Выбирает способ победы (по очкам, сдача, дисквалификация)
3. Приложение автоматически продвигает победителя в следующий раунд
4. Обновленная сетка отображается без перезагрузки

### Для разработчика

**Логи для отладки**:

```bash
npm run tauri dev
# В консоли появятся логи:

# [finish_match] Current match info - round: 1, number: 1, bracket: 789
# [finish_match] Successfully advanced winner to next match
```

**Проверка базы данных**:

```bash
sqlite3 ~/.setki-keeper/data/setki.db
SELECT * FROM matches_cache WHERE bracket_id = ?;
```

## ⚙️ Технические детали

### Алгоритм (Single Elimination)

```rust
// Пример: Match 1.1 → Match 2.1 (slot participant1)
current_round = 1
current_match_number = 1

next_round = 1 + 1 = 2
next_match_number = (1 + 1) / 2 = 1
target_slot = 1 % 2 == 1 ? participant1 : participant2
```

### SQLite операции

1. **SELECT** - получение информации о матче
2. **SELECT** - получение данных победителя
3. **UPDATE** - обновление текущего матча (завершение)
4. **SELECT** - проверка существования следующего матча
5. **UPDATE** - обновление следующего матча (добавление победителя)
6. **INSERT** - добавление в sync_queue (2 записи)

**Итого**: 7 SQL операций в транзакции

### Offline-First

- Все изменения сразу в SQLite (`matches_cache`)
- Синхронизация через `sync_queue` с флагом `synced=0`
- Background worker отправляет на сервер каждые 30 секунд
